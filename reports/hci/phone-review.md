# 手机版复查（2026-11-03，App 1.0.1 之后）

> `phone/` 的截图里是 2026-11-04 换下的旧导师，已经删掉，公开报告保留当时的观察记录。现在的界面见 README 的预览图（`docs/images/`）。

[启发式评估](heuristic-evaluation.md)当时按电脑和 390px 截图做。现在游戏主要以安卓 App 的形式发给同学玩，所以按手机重新走了一遍：1.0.1 加入了“开发中技能只供自学、不点亮”的规则，这条规则也一并检查了。

## 方法

- 标准和严重度沿用原报告：Nielsen 10 条启发式（H1–H10）、0–4 分级；无障碍部分对照 WCAG 2.2 AA。
- 材料：系统 Edge 手机模拟（390×844，触屏、移动视口），按真实流程走：开场 → 选远征 → 营地 → 路线 → 第一课 → 庆祝 → 技能页（有课 / 开发中）→ 综合练习 → 地图 → 复习 → 我的，再把五站全部设为学完、点亮看结局。截图当时在 `phone/`（已删，见开头；截图脚本是一次性的，没有保留；平时看界面用 `node tests/look.mjs --phone`）。顶栏另外在 320px 和 360px 下量了每个标签的位置。
- 局限：仍然只有一名评估者，也没有真人试玩；手机模拟不等于真手机。

## “开发中技能只供自学”这条规则

逻辑上和项目一贯的原则一致：只认游戏能核对的证据，不自评。实现也前后一致：`submitBoss` 拒收没有内容包或没有判分的结果，`shouldLight` 只看判分挑战，`BossView` 遇到没有内容包的技能直接显示练习和答案，“我的”页的点亮数按状态计算，迁移保留真实互动课的结果。单元测试和 e2e 都覆盖了这些情况。

代价在体验上：183 个技能里有 178 个显示“开发中”，地图几乎全是这个状态；五站学完以后，游戏里就没有能继续推进的东西了（见 P5）。这不是界面上的错误，而是内容做到哪儿的问题。

一个边界情况：`satisfied()` 仍然直接读存档里的 `lit`。所以如果一个技能曾经靠旧版内容包点亮，后来内容包被归档，它显示为“开发中”，却仍然算作后续技能的前置。现在只有在 13 个旧包归档前玩过的存档才会这样，不需要处理。

## 做得好的，要保留

- 先猜一猜（标明不计分）→ 讲解 → 即时判题。答错不扣分，错题在本课最后再出一次。
- 答题后底部反馈栏同时给出对错和解释，顶部显示“第几步 / 共几步”。
- 复习页没有到期的题时，会写明下一题什么时候到期；庆祝页也告诉玩家这些题过几天会进复习。
- 开发中的内容都如实标出来，不假装能玩。
- App 的返回键一屏一屏往回退，在第一屏才退出。
