# 课程质量抽查（2026-11-08，v2.0.0 发布后）

用户怀疑 GPT 写课太快（嵌入式最后 5 个技能 68 课，一轮 21 分钟写完），要求：除算法和操作系统以外的远征各抽查课程内容，再完整读一个技能节点，看是否达到验收标准。验收标准就是 [docs/content-authoring.md](../docs/content-authoring.md) 的两条：写给零基础（B1–B7 自动、R1–R6 人读）和知识覆盖面（C1 自动、C2–C5 人读）。

## 结论

**不达标。** 共有 34 个内容包（C.3.2 在边界上）都是同一种模板：每课 1 道先猜、2 张讲解卡、2 道题，选择题几乎全是二选一。自动检查都能通过，事实也基本正确，但人读的几条标准没有做到：

- R4，一课 10–15 分钟：实际只够 2–3 分钟。
- R1，先具体再抽象；R3，编程课先预测再运行：大多没有做到。
- R5，错误选项要用初学者真会犯的错：错误项多是一眼就能排除的“稻草人”。
- C4，学完要做得出综合练习：完整读过的 H.3.2 做不到。

C1 覆盖面检查也只是形式上通过：覆盖表把大纲小节分到了课上，但每节平均只有 24–200 字讲解，相当于一两句话。

今天嵌入式的 5 个包（C.1.2、H.1.1、H.3.1、H.3.2、H.3.3）还多一个问题：79 个术语里有 78 个，是把术语表的定义原样贴在加粗术语后面，只为让 B1“先讲后用”的自动检查通过。贴出来的句子不通，比如“**设备树（device tree）**按节点和属性描述硬件及连接关系的数据。”有几条定义本身也是截断的，比如“自旋锁：，忙等直到锁可用；……”，玩家点开术语时看到的就是这些。

事实层面：抽查到的数值和技术说法都核对过（RC 时间常数、cgroup v2 的 cpu.max 和 memory.max、SYN cookie、SCHED_RR 与 SCHED_FIFO、kmalloc 与 vmalloc、PCA 特征值、散列索引），没有发现错误。问题出在深度和出题方式，不在对错。

## 方法

1. 全量指标：对 47 个包统计每课讲解字数（不算代码块）、每课题数、选择题中二选一的比例、代码与分步例题数量、结业挑战里的二选一数量；再用 `check-coverage` 的小节数算出“每个大纲小节平均有多少字讲解”；另外查“定义被原样贴在术语后面”的情况。
2. 抽查：网络安全、人工智能、DevOps、网站、企业、手机、嵌入式各抽一课，逐项读，核对事实。另读一课操作系统的课作为达标的参照（C.2.1 第 11 课“分页”）。
3. 完整节点：H.3.2 嵌入式系统、驱动与 RTOS（嵌入式远征的目标技能，13 课和结业挑战全部读完），对照 B、R、C 规则和原技能树的综合练习。

## 各远征抽查

| 远征 | 抽查的课 | 看到的情况 |
|---|---|---|
| 网络安全 | S.2.2 第 4 课“连接没建完，等待区先坐满”、第 8 课“给出站和回包写规则” | SYN cookie 只用一句话带过（“把验证所需的信息编码进服务端的初始序号”），初学者读不懂它为什么能省状态；DMZ、DDoS 没有解释。防火墙那课的分步例题和配对题是好的。错误项如“改用更长的 DNS 缓存期”一眼可排除 |
| 人工智能 | A.2.1 第 5 课“把点云压到变化大的轴上”（PCA） | 一张卡里依次出现协方差矩阵、特征值、正交和解释方差；分步例题是对的（[[2,1],[1,2]] 的特征值是 3 和 1，比例 0.75）。练习是 8÷10，另一题是“方差最大一定最能预测类别吗：一定 / 还要验证”。读完不足以理解或做出 PCA |
| DevOps | C.2.3 第 6 课“用完 CPU 额度和用完内存会发生什么” | 这批里较好的一课：有 cpu.max 的换算例题和 docker 命令，事实准确。仍是二选一，标 15 分钟，实际约 3 分钟 |
| 网站 | D.1.2 第 10 课“用散列把等值查找缩小到一组位置” | 可扩展散列、线性散列各一句话；题目是“桶号相同能直接返回吗：不能 / 能，桶号相同就说明键一定相同” |
| 企业 | P.4.4 第 7 课“用消息解耦时间，同时处理重复与失败” | 事件、队列、幂等、一致性挤在两张卡里，没有任何具体的消息或代码；两道题都是二选一 |
| 手机 | P.5.2 第 9 课“在用户需要时申请最小设备能力” | 全是原则陈述（“选择足够窄的访问方式”），没有任何一个平台的权限 API 或代码；选择题错误项是“让所有待办都不可用”“继续最高频率读取并丢掉结果” |
| 嵌入式 | H.1.1 第 5 课“用时间常数预估电容和电感的变化” | 数值都对（3.16 V、4.75 V、20 ms、2 ms），分步例题清楚；但时间常数的定义是贴上去的句子，“一阶响应”“e 的负一次方”对零基础没铺垫；“断开电感回路需要安排电流的去处”没讲续流二极管 |

## 完整读一个节点：H.3.2 嵌入式系统、驱动与 RTOS

13 课，每课都是先猜 + 2 卡 + 2 题；结业挑战 8 题，其中 4 道二选一，3 道是 6×512+2048 这样的一步算术。

| 规则 | 结果 |
|---|---|
| B1 先讲后用 | 形式上通过。16 个术语全部是贴上去的定义（语法不通），其中 4 条定义本身残缺（“自旋锁：，忙等……”“抢占：是让……”）。不在 `data/jargon.yaml` 里的行话没被拦下：Cortex-M、SPL、U-Boot、DRAM、compatible、reg、pinctrl、probe、cdev、file_operations、modprobe、tick、SCHED_FIFO、IRQ 亲和性、PREEMPT_RT、raw_spinlock、kmalloc/vmalloc、oops、debugfs、kgdb、Magic SysRq、lockdep 都没解释，往往一张卡里挤好几个 |
| R1 先具体 | 不达标。卡片是要点摘要，几乎没有具体例子 |
| R2 分步例题 | 部分达标。只有 2 课有 reveal（启动搬段、响应时间） |
| R3 编程先预测再运行 | 不达标。整包 0 段代码，FreeRTOS 的 xQueueSend、xTaskDelayUntil 只在文字里出现 |
| R4 一课 10–15 分钟 | 不达标。平均每课约 230 字讲解加 3 道题，标 10 分钟，实际 2–3 分钟 |
| R5 讲误解 | 不达标。选择题全是二选一，错误项多是“可以，所有 RAM 总会保留旧数据”“不需要，只要重启就永远不会再挂”“认定故障已经修复”这类 |
| R6 数值核对 | 达标。`tests/content/H.3.2.verify.py` 通过 |
| C1 覆盖表 | 形式上通过。70 个小节分到 13 课，比如 `boot-linux` 一课（两张卡）同时负责 x86 启动、ARM 启动、U-Boot 配置、命令、环境、脚本和 distro boot；平均每节 42 字 |
| C4 综合练习做得出 | 不达标。综合练习第 2 问要求用 FreeRTOS 风格的 API 写出两个任务和队列，第 4 问要求写出字符设备驱动结构（file_operations、copy_to_user、probe），课里从没展示过这些代码 |
| 事实 | 没发现错误：SCHED_RR / SCHED_FIFO、kmalloc / vmalloc、PREEMPT_RT 并入主线、看门狗、A/B 更新的说法都对 |

课的文字和原技能树综合练习的参考答案高度重合（向量表、.data/.bss、SPL、U-Boot、lockdep……），像是把参考答案拆成要点再配题，而不是从零教会。

## 自动检查为什么没拦住

- B1 只查 `data/jargon.yaml` 里有没有定义，不管定义写得通不通，也查不到清单以外的行话；定义可以直接贴。
- B2、B3 只限制“连续不超过 2 张卡、每卡不超过 240 字”，模板正好卡在上限以内。
- C1 只查每个小节有没有被分给某一课，不管那一课讲了多少。
- R4、R5、C4 本来就靠人读。这批包没有做零基础通读，也没做覆盖面核对。
- e2e 只证明正确答案会被判对。

## 下一步要用户定的

这 34 个包共 497 课（加上 C.3.2 是 508 课），在除算法外各远征里占 18%–87% 的课。可选方向：

1. 按标准重写，先从共用最多的站开始：P.2.4、P.4.5、P.5.1、P.4.3、P.1.2 被 3–5 条远征共用。工作量接近从头写这些技能。
2. 先把受影响最重的远征（企业、手机、网站）改回“开发中”，等重写好再开放，发一个 2.0.1 说明；地图上的课仍能学。
3. 无论选哪个，都先补自动检查，防止再出现：
   - 每课讲解字数和题数的下限，以及按内容估算的时长要和 `minutes` 对得上；
   - 选择题至少 3 个选项的比例，结业挑战里二选一的上限；
   - 查出“定义原样贴在术语后面”和以标点或“是”开头的残缺定义；
   - 覆盖表里每个小节至少要有多少讲解。

另外，[docs/development.md](../docs/development.md) 和 README 里“课程都按两条标准写好”的说法，对这 34 个包不成立，需要随所选方向一起改。
