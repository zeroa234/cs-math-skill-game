# 宣传片第二版：方案

状态：**方案已定，宣传片还没开工**（2026-11-05）。改名已在 1.3.1 完成（见下文“改名”）。第一版已整个删除（代码、截图、配音、成片），只在 git 历史里（提交 `a1577962`）。做完后本文件改写成“怎么重新生成”的说明。

要做两个版本：**纯音乐 PV** 和 **广告向**。两版内容不同，各有各的故事、镜头、顺序、字、音乐和结尾（见下文“两个版本各讲各的”）。共用的只有制作材料：同一轮游戏截图、导师精灵、游戏音效、像素界面组件、落版必须写的信息。两版都用新名字 **《计算机大学习！》**，都 ≥ 60 秒。

## 为什么重做

第一版（1 分 48 秒，鲸鱼娘旁白，已删除）被否定，原话是“不像广告或 PV，而是在念游戏”。逐帧看过后的原因：

- 开头 10 秒讲的是作者（“上次我把计算机专业做成了一棵技能树”），游戏本身第 10 秒以后才出现。
- 七成画面是整窗截图装在框里，字小得要暂停才读得清，字幕再把旁白复述一遍。
- 一拍讲一个功能，从头到尾一个强度，没有起伏。
- 念数字：124 课、183 个技能、957 处核对，还有终端输出。
- 配乐是游戏里的循环曲，本身没有起伏。

## 定位（用户原话整理）

游戏是**照着多邻国做的**，为的是**帮学生学习**；在多邻国那套之上**加了技能树**这些内容（整个专业学什么、先学什么、去哪深入）；是**非商业的开源游戏**。

宣传片只说这一件事，不去单挑某个功能当卖点。“自己当调度器”算不上独特：OSTEP 教材自带 `scheduler.py`、`paging-policy.py` 模拟器，Brilliant 也是一小课一小课、全靠动手的计算机课程。

## 硬约束

- **每版都要 ≥ 60 秒**：用户要参加一个只收 1 分钟以上视频的限时活动。目标 63 秒，留出余量，成片用 `ffprobe` 量。
- 活动的其他规则（截止日期、横屏还是竖屏、分区、话题）**还没拿到，开工前先问用户**。在问到之前，按第一版的规格做：1920×1080、30 fps、H.264 + AAC、-16 LUFS。

## 纯音乐 PV：从第一颗星到整片星图

一个看不见的玩家，每天学一小课，星星一颗颗亮起来，最后整个专业都亮了。多邻国式的“每天一课、连续打卡”，靠营地里“第 N 天”和越烧越旺的火苗演出来；“多了技能树”，靠结尾整片星图亮起来演出来。全程不解释。

| 段 | 时间 | 画面 | 音乐 |
|---|---|---|---|
| 冷开场 | 0–6 s | 黑场里，游戏对白框逐字打出妹妹的第一句“欢迎来到星图学院。”（游戏开场原话，带打字音）→ 一颗像素星“叮”地亮起 → 镜头猛地拉开：它是夜空里那棵星星连成的树最底下的一颗，其余全暗 | 前奏，起拍落在星星亮的那一下 |
| 引子：每天一课 | 6–20 s | 一天的循环：营地（“第 1 天”）→ 路径上点“开始” → 猜、看、做三拍快切 → 答对，课程结算的星星一颗颗弹出、导师庆祝 → 火苗亮起。第二遍、第三遍剪得更快：“第 2 天”“第 3 天”……火苗越烧越旺。中间答错一次：红色反馈栏，导师 `coy` 害羞，算一个小笑点 | 平稳段，切在强拍上 |
| 升温：越学越深 | 20–40 s | 两位导师站在画面同一个位置不动，背后的领域背景（`assets/bg/lane-*.png`）每拍换一张，前景换成那个领域的实验特写，只裁出在动的那块。三个一组，组和组之间用一个重音隔开（闪白，导师换个动作）：Python 单步 → 栈和队列 → 哈希表 ‖ 调度做出竞态（x = 1，屏幕一红）→ 分页 → 页面置换 ‖ 图搜索一圈圈扩开 → 矩阵变换 → 梯度下降 | 渐强，切得越来越快 |
| 转折：考试 | 40–46 s | 音乐骤停。结业挑战，计分一题一题往上跳，逼近八成那条线，背景只剩一下一下的低音 | 骤停，只留低音 |
| 高潮：点亮 | 46–55 s | 过线！点亮页：妹妹 `cast`、姐姐 `dance`、像素彩带 → 镜头从路径往后拉，Blender 的塔一路亮到塔顶 → 再拉成整片星图，连线一条条接上，整棵树亮起来 | 最高点，整棵树全亮的那一下戛然而止 |
| 落版 | 55–63 s | 静下来的星图，《计算机大学习！》像素大标题砸下来（震屏加像素粒子），信息一行行出来（见“落版必须有的信息”）。最后营地的火苗 +1，响一声游戏音效 | 尾音 |

界面里的“第 N 天”和课程结算的数字都取游戏真实画面，不编。领域背景和实验要对得上：实验属于哪个技能，就用那个技能所在领域的背景。

## 广告向：两位导师告诉你

两位导师当主持人，像多邻国的广告那样，用学生都熟的场景开头，把定位直接说出来：一天一小课、答错不扣分、整个专业一张图、免费。

| 段 | 时间 | 画面 | 台词（草稿，开工前由用户定稿） |
|---|---|---|---|
| 痛点 | 0–7 s | 一本超厚的像素《操作系统》课本“咚”地砸下来，姐姐被压在下面，只露出一只手 | 姐姐：“操作系统……这么厚？！”<br>妹妹：“期末前一晚才翻开，当然厚。” |
| 解法 | 7–17 s | 妹妹掏出一部像素手机，屏幕里是蜿蜒的关卡路径，关卡一格格弹出来 | 妹妹：“拆开来，一天一小课，几分钟就够。” |
| 怎么学 | 17–30 s | 手机里演一课：先猜 → 选错，红色反馈栏，姐姐 `coy` 害羞 → 答对，星星弹出，火苗亮起 | 姐姐：“先猜一猜，再看讲解，再动手做。”<br>妹妹：“答错也不扣分，告诉你错在哪。”<br>姐姐：“每天来打个卡就行！” |
| 不一样的地方 | 30–43 s | 姐姐把手机往外一推，镜头拉出整片技能星图；点开一个技能页，“去哪深入”那块放大 | 妹妹：“整个计算机专业要学什么、先学什么，都画在这张图上。”<br>姐姐：“每一章还告诉你，去哪本书、哪门公开课接着学。” |
| 动手 | 43–50 s | 三个实验快切：调度、页面置换、图搜索 | 姐姐：“看不懂的地方？自己上手试试！” |
| 承诺 | 50–55 s | 结业挑战过线，点亮，彩带 | 妹妹：“考过了，这颗星才算点亮。不收钱，也没有广告。” |
| 落版 | 55–63 s | 两人站在两边，中间是《计算机大学习！》大标题，信息一行行出来（见“落版必须有的信息”）。最后姐姐从画面边上探头 | 两人：“计算机大学习！”<br>妹妹：“安卓、电脑、网页都能玩，下载在简介里。”<br>姐姐：“今天的大学习，打卡了吗？” |

时间是按每秒 4–5 个字估的；配音合成后按实际时长调时间轴，总长仍要 ≥ 60 秒。

台词里每一句都对得上游戏：
- “先猜、再看、再做”“答错不扣分，告诉你错在哪”“去哪本书、哪门公开课”：游戏开场导师的原话（`src/game/ui/Intro.jsx`）。
- “几分钟就够”：README“每课几分钟”。
- “考过才点亮”：结业挑战第一次答对 ≥ 80%，没有自评。
- “不收钱，也没有广告”：游戏除了每天一次的更新检查，不发任何网络请求（`docs/android.md`）。

写法规则（用户明确提过）：
- 要像角色真会说的话，或者像观众看完转述给朋友的话。
- 不要口号堆叠，不要斜杠并列，不要“亲手当一回 X”这类腔调。
- 不写游戏里没有的东西。

## 技术做法

**从头做，不沿用第一版的任何文件**（用户 2026-11-05 决定）。第一版的代码、截图、配音、Blender 渲染、成片和封面都已删除：游戏改了名，旧截图和旧配音里都是旧名字；旧场景和“整窗截图加字幕”的版式也正是第一版失败的原因。

工具仍建议用 Remotion：画面要靠代码生成，做事的 agent 没法操作 After Effects 这类图形界面软件；Remotion 画的是网页（React + CSS），游戏的像素字体、像素边框和截图都能直接用，配音和音效也能按帧对齐。新工程放 `src/promo/`，脚本放 `scripts/promo/`，文稿和数据放 `data/promo/`，成片放 `output/promo/`（沿用本项目的目录约定）；用当时的稳定版，版本在 `package.json` 里写死。

Remotion 官方现成的包，自己写之前先看它们够不够：
- `@remotion/transitions`：段与段之间的转场序列。
- `@remotion/layout-utils`：量字宽、让大字刚好撑满一行（`fitText`）。
- `@remotion/lottie`：以后如果有人用 After Effects 或 LottieFiles 做了动画，可以直接放进来。
- `@remotion/motion-blur` 不用：运动模糊会把像素画糊掉。

两版在同一个工程里，各是一个 composition（`PV`、`Ad`）。只共用底层组件（像素边框、对白框、手机框、导师精灵、大字、音效），场景各写各的。

### 第一版踩过的坑

这些是关于游戏和工具的事实，不依赖旧文件，从头做照样会遇到：
- **截图要可复现。** 存档里打开“减少动画”（`settings.reduceMotion`），这样角色不动、不放彩带、开场文字直接显示；要动的部分都在视频里补。
- **导师在视频里补。** 截图时把导师精灵藏起来，记下她们站的位置，视频里在原位按帧播放 `assets/cast/sprites/<black|blue>/<动作>.webp` 动画条。动画条的帧怎么排，看游戏的 `src/game/ui/cast.jsx`。
- **截图时自动答题。** 用游戏自己的 `tests/lib/play.mjs` 按正确答案往前走；浏览器统一用 `scripts/lib/edge.mjs` 开（系统 Edge，临时文件放 `temp/`）。
- **开场对白要等字出完再点。** 每点一下之前等这句打完，否则这一下只是“把这句打完”。
- **页面置换按标签找页。** 每一步可选页的顺序跟着页框变，要按页的标签找要点的那个，不能按位置。
- **游戏音效离线合成。** 从 `src/game/app/sound.js` 读出 ZzFX 参数，用 ZzFX 1.4.0 的 `buildSamples` 合成成 wav。
- **Remotion 的无头浏览器只装一份。** 第一次渲染会把它下载到当前目录的 `node_modules/.remotion`（约 110 MB），所以脚本都在 `src/promo` 里跑。
- **Remotion 的临时文件别写到 C 盘。** 它会往系统 TEMP 写打包副本和 Chrome 配置，曾经占到 70 GB。渲染、抽帧前把 `TEMP` / `TMP` 指到 `temp/promo/tmp`，完了删掉。
- **Blender 像素 3D：**
  - `render.filter_size = 0` 才是硬边；
  - 几段画面共用一套调色板（ffmpeg `palettegen` / `paletteuse`，`dither=none`），否则段与段、帧与帧之间颜色会跳；
  - 中间片用 yuv444p，像素边上不串色；
  - 发光太强会把颜色洗成白色。
- **配音管线不在本仓库。** 用 `projects/os-review-bilingual` 的 Breeze 管线（`narrate.py --out`、`align-narration.py`、`qc-narration.py`、`mix-bgm.py`）。
- **第一版各步用时**（RTX 3080）：Breeze 合成 13 句约 40 s；截图约 3.5 分钟；Blender 两段约 8 分钟；成片渲染加混音约 10 分钟。

第一版的旧代码只在 git 历史里，要查某个做法可以用 `git show a1577962:projects/cs-math-skill-game/<路径>`（比如 `src/promo/src/lib/sprite.tsx`、`scripts/promo/capture-game.mjs`）。只当参考，不要恢复。

要新做的：
- **节拍网格**：用现成的 [allin1](https://github.com/mir-aidj/all-in-one)（All-In-One Music Structure Analyzer）算拍点、强拍和段落（前奏 / 主歌 / 副歌……），写进 `src/promo/public/build/beats.json`。它在 Windows 上依赖的 NATTEN 不好装，放在 WSL 里跑。PV 版画面取帧用“第几段第几拍”。广告版按台词逐字对齐的时刻取帧（对齐用 Breeze 管线的 `align-narration.py`）。
- **动效组件**：
  - 像素手机框。
  - 裁剪推近的镜头（只露出要看的那块）。
  - 大字和对白框的弹入、震屏、像素粒子。
  - 经验值和火苗的数字跳动。
  - 落版页。
  - PV 版段与段之间硬切卡拍，像素溶解只在进落版时用一次。
- **配乐**：
  - PV 版要一首有前奏、渐强、高潮、尾声的曲子（游戏里的循环曲不行）。从游戏的 25 首 CC0 曲子（`data/music.yaml`）和 `projects/kurumi-fx-rogue/assets/bgm/tracks.json` 的 CC0 曲库里，用 allin1 的段落加响度曲线挑 2–3 首候选。**做事的 agent 听不到声音，由用户试听定**。
  - 广告版用轻快的垫底曲，也挑 2–3 首候选。
  - 两版都以 -16 LUFS 出片。
- **配音（广告版）**：用 os-review-bilingual 的 Breeze 管线（`narrate.py --out`、对齐、质检）。现在只有一个鲸鱼娘参考音色，两姐妹要两个声音：给另一位找第二个参考音，或者同一音色调出两种语气。先各合成一句给用户听，用户定了再合成全部。
- 输出放 `output/promo/pv/`、`output/promo/ad/`（成片、混音前的画面、封面）。

## 做的顺序和验收

1. 问用户活动规则：截止日期、画面比例、分区、话题。
2. ~~改名~~：已在 1.3.1 完成。
