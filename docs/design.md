# 设计说明：为什么这样玩

目标：零基础的人能上手、愿意继续、真的学进去。依据是 `reports/research/similar-games.md`（pi 调研，主代理抽查过关键引文）里的同类产品和学习科学结论。下面每条写“做了什么 → 依据”，依据编号对应那份报告的小节。

## 一张树，两种看法

- **远征（路线）**：选一个目标——“我的远征”（作者自己选的操作系统）、八条推荐远征（按开发者调查和公开路线图选，见 [recommended-routes.md](recommended-routes.md)），或者 183 个技能里的任何一个——游戏从技能树里自动推出它的全部必须前置，按前置顺序排成一条路，像 Duolingo 的单线路径一样只问“下一步做什么”。推荐前置放在旁边当“支线”，不挡路。→ A1（Duolingo 从树改成路径，理由是学习者常问“我是不是用错了方式”）、A2（Brilliant 承认它把前置画得比真实简单，为了清晰的里程碑）。
- **地图**：183 个技能全部画出来，悬停看必须前置链。这是原技能树项目的卖点，保留真实的 DAG。→ A9（科技树是 DAG）。

## 第一次打开：开场，然后选路线

第一次打开播放一段可跳过的开场：标题画面，两位导师用 4 句话讲清“这是什么（183 个技能的星图）、怎么学（一小课：猜、看、做，答错不扣分）、去哪深入”，然后直接进入“选远征”。→ 启发式评估 #1（H10 帮助与说明：改版前要先读一大段文字）。

“选远征”分三块：**我的远征**（宽卡片：领域背景图 + 由技能树写出的介绍）；**推荐远征**（八条；每一站都写好的才开放，现在开放的是“算法”，其余灰色、标“开发中”，按钮不可点，卡片上写着“已按零基础标准写好 x / n 站”）；**自己定目标**（开发中，开放后任何技能都能当目标，先预览要走哪些站再出发）。开发中的路线打开后只显示要走的站，不给可玩的关卡路径，也不会变成当前远征。不再标“新手推荐”：所有路线都从程序设计基础或数学基础起步，那个理由站不住。→ #2（H3 用户控制、H7 灵活）；H1 系统状态可见（开发中写明还差几站）。

## 路线的样子：一条蜿蜒的关卡路径

每个技能是一个“单元”色带（颜色是它的领域色），每课是一个圆形关卡，左右蜿蜒排开，每换一章在关卡之间标出“第 N 章 · 章名”；完成的关卡变金色并显示星级，锁住的关卡点了只响一声“锁住”音。下一关上方弹出“开始”气泡（章名、约几分钟），导师站在旁边。故事、自动推导的说明、KTH 对照收进“关于这条路线”。→ #3、#4（H8 简洁美观、H6 识别而非回忆）；A1（Duolingo 的路径）。

## 一课里的反馈

检查/继续按钮和判定结果固定在屏幕底部（位置不变，H4 一致性），答题后整条栏变绿或变红并配音效，解释写在栏里；左边的导师答对跳起来、答错捂脸，说一句话。退出一课前确认（H3、H5）。完成后是庆祝页：星星依次弹出配音，经验和一次答对数，两位导师跳舞/施法。→ #5–#9。

## 导师、声音和画风

- **两位导师**：鲸鱼娘姐妹（角色设计 ZipZipPipe，CC BY-NC 4.0；2026-11-03 换掉原来以已有作品角色为原型的两位）。黑发的鲸鱼妹妹沉稳（开场讲解、复习时陪着），蓝发的鲸鱼姐姐活泼（课里陪练）——设定里姐姐反而更孩子气、妹妹更成熟。像素小人只用全年龄的日常动作。角色集中在 `src/game/ui/cast.jsx` 和 `assets/cast/`，换角色不动界面代码；没有 `assets/cast/` 时（公开仓库）游戏不画导师，`<html>` 带 `no-cast` 类，样式表把导师占的位置收起来。
- **声音**：ZzFX 在播放时合成 8-bit 音效，没有音频文件；顶栏可以静音，设置存进存档。只在点击或按键之后出声（浏览器也只允许这样）。
- **背景音乐**：按玩家在做什么换曲：开场、逛营地和路线、上课和复习、结业挑战。上课用每种风格里最安静的一组，结业挑战才用战斗曲，免得做题时被抢注意力。风格有 4 种可选（像素 RPG、8-bit 芯片、中世纪奇幻、Lo-fi 学习），音量单独可调，也能只关音乐、保留音效；顶栏喇叭是总开关（H3 用户控制）。曲目全是 CC0，来源见 `assets/music/README.md`。
- **画风**：像素奇幻“星图学院”，文字、界面和美术是同一种像素风（2026-11-03 用户指出字体和像素风格没和界面统一，改版前正文是系统字体、卡片是圆角）：
  - **字体**：所有文字都用 Fusion Pixel 12 px（OFL；正文用等宽以外的比例版，代码用等宽版），只取 12 / 18 / 24 / 36 px。作者的屏幕是 200% 缩放，这几档都落在整数个物理像素上，字形不发糊；100% 缩放下 18 px 会是 1.5 倍，略不均匀。像素字体没有粗体和斜体，浏览器“伪粗体”会把像素抹花，所以关掉（`font-synthesis: none`），课文里的重点改成荧光笔底色。公式仍用 KaTeX，保证可读。
  - **边框**：没有圆角。卡片、按钮、输入框、选项都是方角、切掉一个像素角（`--notch`）、底边加厚的硬阴影，线宽统一是一个界面像素（`--p` = 3 px）；描边颜色 `--rim` 对背景有 3:1 对比（WCAG 1.4.11）。关卡按钮是 12×12 网格画出的像素圆。
  - **图标**：全部换成 pixelarticons（MIT，24 格网格，实际笔画是 12 格），尺寸等于字号，和字体落在同一个像素网格上；不再用 emoji。
  - **焦点**：被裁成像素角的控件把焦点框画在框内（外圈深色 + 内圈底色），在浅色、深色和彩色按钮上都看得见。
  - 背景是本机生成后像素化的 480×270 图，放大时不插值。按钮按下会沉一个界面像素。
  - 查看效果：`node tests/look.mjs [--dark] [--phone]` 在 1440×900、200% 缩放（手机 390×844、300%）下截主要界面到 `temp/look/`。
- **减少动效**：系统设置“减少动态效果”或“我的”里的开关打开时，精灵只显示第一帧、彩带不放、动画关掉。

## 一课的形状：先猜，再看，再做

一课 10–15 分钟，讲一点、练一点（2026-11-03 改：原来“每章一课 5–10 分钟、2–4 张卡讲完再做 3–5 题”的形状把讲解压成了提纲，用户评价“像站在已经学会了的人的视角上写的”，小白学不懂）：

1. **先猜**（不计分）：讲之前先问一个凭直觉能猜的问题。→ A2（Brilliant：先提问再讲）、B1（检索练习）。
2. **一张卡讲一个想法，紧跟一个问题**：连续讲解不超过两张卡；每个新术语先讲清再用（点一下术语随时能看它的意思，复习时也能）。→ Mayer 的分段原则和预训练原则、专家盲点，见 `docs/content-authoring.md`“写给零基础的标准”。
3. **分步例题**：要好几步才能做出的题，先给一张逐步揭开的例题（每步写清“这一步要达成什么”），再给一道做了一半的题，最后才是独立的题和换情境的题。→ B4（worked example 与渐隐）。
4. **练习**：即时判题，每题都有“为什么”的解析，错误选项写明错在哪。答错不扣任何东西，这题在本课最后再出现一次；第二次还错就给解析、继续。→ A1（Duolingo 官方承认红心让初学者中途耗尽的概率是 2 倍，后来改掉）、B5（信息性反馈）。

一章内容多就拆成几课，课按“第 N 课”编号并标出所属的章。这条标准能自动检查的部分（术语先讲后用、连续卡片数、卡片长度、操作题前有演示、不跳步、不自评、结业题数量）由构建强制执行，每个内容包都必须通过（当初衡量旧包差距的审计表已随旧包归档）。

**讲得懂，也要讲全**：每个技能教到哪里，以原技能树 skill-tree 给它的大纲、CS2023 匹配和综合练习为准。大纲的每一节都要有一课教，或写明为什么不教。依据是用户 2026-11-03 的要求：“以后不仅考虑新手，也要考虑知识覆盖面”。规则见 `docs/content-authoring.md`“知识覆盖面标准”。

现状见 `docs/content-authoring.md`“知识覆盖面标准”末尾：“我的远征”的 5 站都已按两条标准写完。

星级只看“第一次就答对”的比例，用来提示哪里还不稳，不卡进度。

## 角色扮演，再换回符号

难的机制先让玩家“当它”：当调度器排甘特图、当页表翻译地址、当操作系统决定哪个线程先走一步（亲手制造丢失更新和死锁）、当页面置换算法选换出哪一页、当 BFS/DFS 决定下一个点。当梯度下降选学习率、当拓扑排序排先后，课里已经在用；当 Dijkstra 一个个确定最短距离、当 Ford–Fulkerson 一条条找增广路，算法分析与设计的课在用；当一个神经元调权重的组件也已写好，等相应技能的课用到（实验室条目暂存在 `archive/src/game/ui/lab-archived.js`）。图算法里平局由玩家自己选，任何一种算法能产生的顺序都算对，判的是算法规则，不是课本上某一种打印结果。讲解卡里组件显示队列/栈和“下一步可以选”，并能自动走一步；练习里这些要自己记着。之后同一课里一定有纯数字/代码的题把符号换回来。→ A6（The Deadlock Empire）、A5（Human Resource Machine 的具身隐喻）、A8（DragonBox：符号要显式换回来，并检验迁移）、A7（TensorFlow Playground）。

**实验室**只放课里遇到过的实验：学完一课，如果这课里有第一次遇到的实验，实验室就多一个，并提示“实验室多了一个实验”（2026-11-04 用户定）。没遇到的不显示、不上锁：实验室是学过以后随便再玩的地方，不是另一套要解锁的关卡，也不让新玩家一进来就面对一堆没学过的组件。

代码题的“单步运行”是真实的 Python 执行轨迹：构建时运行代码并记录每一步，所以显示的值不可能和真实 Python 不一致。

## 复习由系统排，复习等于前进

做过的题进入复习卡组，用开源的 FSRS 算法（ts-fsrs，FSRS-7）排下次出现的时间：第一次就答对记 Good，提示后或重试才对记 Hard，答错记 Again。复习不限次数、不消耗任何东西，没有“技能裂开”。→ A1（Duolingo 移除 cracked skills，改为“练习内建在路径里”）、B2（间隔效应）、C（FSRS）。

## 两层状态：记忆层和能力层分开

- **记忆层**：每道题一张 FSRS 卡片，决定什么时候再问。
- **能力层**：技能状态 未解锁 → 现在能学 → 学习中 → 已点亮 → 熟练 → 精通（还没有互动课的技能只有“开发中”）。点亮 = 结业挑战第一次答对 ≥ 80%（见下一节）；熟练 = 这个技能的每张卡都复习过、记忆稳定性 ≥ 7 天；精通 = ≥ 30 天。熟练和精通由复习自然达到，不会因为没上线而掉级。→ C5（FSRS 适合原子记忆项，不适合 20 分钟的综合题）、A3（Khan 的掌握度分档）。

## 结业挑战：只认游戏能核对的证据

不让玩家给自己打分，也没有“我已经会了”的按钮（2026-11-03 用户要求去掉：自评不是学会的证据）。点亮只看游戏能核对的东西：

- **有互动课的技能**：结业挑战是内容包里的自动判分题，和课一样在同一个播放器里一题一题做（H4 一致性）。开始前说明规则：**第一次就答对 ≥ 80%（不看提示）才点亮**；答错的题当场给解析、最后再练一次，但不算进点亮；没过可以马上再挑战，不扣任何东西。80% 取掌握式学习的常用门槛 → B6。原技能树的综合练习放在点亮之后，作为不计分的延伸练习。
- **跳级挑战**：同一套题，不用先学各章；同样要第一次答对 ≥ 80%。只有能自动判分的技能才有跳级。→ B4（专家反转效应：已会的人不该被迫重看讲解）。
- **还没有互动课的技能**：标为开发中，章节教材、前后置和原技能树综合练习全部开放，参考答案可直接展开。不提供“读完了”，不记录完成、不点亮：读过资料、看过答案都不是学会的证据（2026-11-03 起，之前是按章打卡后做综合练习点亮）。互动课做好以后，用重写后的自动判分挑战点亮。

规则在 `src/game/core/rules.js` 的 `shouldLight` 和 `src/game/core/lesson.js` 的 `bossFlow`、`PASS_SHARE`；旧存档怎么迁移见 [architecture.md](architecture.md)“存档”。

## 每一章都告诉你去哪深入

游戏帮你入门，真正学透要读教材。每一章都列出原技能树核对过的中英文资料里对应的章节（标注免费/付费、部分覆盖），可以在“我的”里切换中文优先、英文优先或双语。

## 元游戏少而精

只保留：学徒等级（经验）、连续学习天数、成就（描述“你会了什么”，如“看懂操作系统”）。没有排行榜、没有货币、没有体力。→ A2（Brilliant：避免塞太多游戏激励）、B7（游戏化效应随时间衰减甚至为负；有形奖励削弱内在动机）。

## 章节编号

原项目的知识导览图沿用教材自己的节号，所以“极限与连续”从 2.2 开始。游戏里每个技能的章统一编号 1…n，顺序规则见 `reports/chapter-order.md`；教材节号只作为“来源章节”标签出现在“去哪深入”和知识地图里。

## 没做的（有意或暂缓）

- **推荐远征和自己定目标还没开放**（用户 2026-11-03）：先只重构“我的远征”（操作系统）经过的 5 个技能；推荐路线已经选定（[recommended-routes.md](recommended-routes.md)），等各站的课按零基础和覆盖面两条标准写好再逐条开放（`data/routes.yaml` 的 `status`、`customGoals`）。第一条开放的是“算法”（2026-11-04，4 站：证明方法与离散结构、程序设计基础、数据结构、算法分析与设计）。

- **地图迷雾**（A9-14 建议默认只显示下一步可达节点）：没做。地图默认就是一张能缩放的全图，远征页已经承担“只看下一步”的角色。
- **优化维度**（A5：过关之外的“更短/更快”）：暂缓，等更多 sim 有自然的优化指标。
- **交错复习的说明**：复习本来就跨技能混排，界面里还没有专门解释为什么要混着练（B3 建议显式说明）。
