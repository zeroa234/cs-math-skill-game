# 归档：模板化的短课（2026-11-08）

这里是 v2.0.0 里 35 个技能的互动课，2026-11-08 抽查后撤下，游戏不再读取。抽查结果见 [reports/quality-audit-2026-11-08.md](../../reports/quality-audit-2026-11-08.md)。

它们都是同一个模板：每课 1 道先猜、2 张讲解卡、2 道题，选择题几乎全是二选一。构建的自动检查（B1–B7、C1）都能通过，事实也基本正确，但不满足 [docs/content-authoring.md](../../docs/content-authoring.md) 里要人读的几条：一课 10–15 分钟（实际 2–3 分钟）、先具体再抽象、编程先预测再运行、错误选项要是真实的误解，以及学完要能做出原技能树的综合练习。每个大纲小节平均只有 24–206 字讲解，达标的包是 233–1266 字。C.1.2、H.1.1、H.3.1、H.3.2、H.3.3 的术语定义是贴在加粗术语后面凑出来的，句子不通。

| 目录 | 内容 |
|---|---|
| `content/` | 35 个内容包（`version: 2` 格式） |
| `coverage/` | 它们的覆盖表：大纲每一节对到哪一课。小节清单可以直接复用，但“由哪一课教”要按重写后的课重新填 |
| `verify/` | 数值核对脚本（读的是原来 `data/content/` 的路径，归档后不再运行） |

技能：A.2.1、A.2.3、A.4.1、C.1.2、C.2.2、C.2.3、C.3.2、C.4.2、D.1.1、D.1.2、D.1.3、H.1.1、H.1.2、H.3.1、H.3.2、H.3.3、M.1.3、M.1.4.1、M.6.1、M.6.2、M.6.2.2、P.1.2、P.1.3、P.1.4、P.2.4、P.4.1、P.4.3、P.4.4、P.4.5、P.5.1、P.5.2、P.5.3、S.2.2、S.2.3、S.3.1。

**重写时**：抽查到的事实和数字没有发现错误，可以参考；但不要照这里的写法写。按 content-authoring.md 先写覆盖表，再写课，再写核对脚本；新包写好、验收通过后，把这里对应的三个文件删掉。

**存档**：玩家在 2.0.0 里点亮过的这些技能，存档里还留着点亮记录；包撤下后这些技能显示“开发中”，过期的复习卡在读档时自动丢掉（`src/game/app/state.js`）。重写的包回来时，这些旧的点亮记录会让技能直接显示为已点亮，要在重写的包上线前决定怎么处理。
